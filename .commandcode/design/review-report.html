// PRIORITY ISSUES
P1 — COLOR

Primary CTA deviates from the brand button rules

src/styles/global.css: .btn uses background:var(--teal-text) #2d5867 and a rust hover. The WebberZone brand system reserves teal #4a7c8a for button backgrounds and teal-dark #3d6875 for button hover; rust is for secondary buttons and link hover only. The CTA currently reads navy, not brand teal.

FIX: .btn background:var(--teal) (white text passes AA at 4.62:1); hover #3d6875. Keep rust for secondary hover states.
P1 — COLOR

Code block is themed GitHub, not WebberZone

The snippet page renders the source in Shiki's github-dark theme (#24292e with GitHub's red/green/blue palette) inside the brand-navy .source-shell. Two different dark surfaces stack, and the site's primary artifact — the code itself — is the only region using an off-brand colour system.

FIX: Custom Shiki theme on a navy surface with teal/amber/stone token hues, consistent with the .source-shell chrome.
P1 — LAYOUT

"On this page" omits the page's main sections

Toc.astro collects only .markdown-body h2s; Requirements, Source, and Details are rendered outside that wrapper. The TOC lists 2 of 5 sections — Source, the reason the page exists, is unreachable from it. Guide pages include everything, making the omission visibly inconsistent.

FIX: Generate the TOC from all article h2s (move sections into the collected scope, or scope the query to the article container).
P1 — INTERACTION

Filtering to zero results is a dead end

SnippetBrowser.astro render() replaces the grid with zero cards when nothing matches; the only feedback is "0 of 22 snippets". No message, no reset path. Reproduced live in the browser.

FIX: Render a "No snippets match these filters" empty state with a clear-filters action when items.length is 0.
